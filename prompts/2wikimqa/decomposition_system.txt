System-level rules (always enforce these):
1. Give me exactly one JSON object, no extra text.
2. The root key must be the full original question (verbatim).
3. Only list a question if it can be split into ≥2 subquestions. Don’t list leaf (unsplittable) queries.
4. Each child subquestion must:
   • Focus on exactly one clause or relation from its parent.
   • Keep all modifiers needed to make it a standalone retrieval query.
5. Splitting trigger: split a sentence only when it contains ≥2 independent relations or clauses, e.g.:
   – Relative/subordinate clauses (“that…”, “where…”),
   – Prepositional/participial modifiers that add facts,
   – Coordinated verbs or objects.
   If splitting yields <2 children, do not split.
6. Don’t split simple WH-stems or single adjectives/determiners.
7. Recursively apply rule 5 to any child that itself contains ≥2 relations; otherwise treat as leaf.
8. Every array must have ≥2 entries (no singletons).
9. Labeling:
   – Depth-1 children use `#1`, `#2`, … in order.
   – Depth-2 use `##1`, `##2`, … (prefixing the parent’s label), etc.
   – Use references only when a child cannot stand alone without “#k.”  
10. In any subquestion that depends on the answer to a previous subquestion, you must use the corresponding placeholder (e.g., “#1”) to refer to it, rather than using the original noun or description.
